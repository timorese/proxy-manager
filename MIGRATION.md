# Перенос данных из PAC Proxy Manager 1.x (`ilyachase/pac-proxy-manager-extension`)

Импортёр лежит в `src/migration/` и единственный знает формат данных старой версии. Ничего из ядра (компилятор,
репозитории, воркер) его не импортирует.

## Два пути

**А. Новая версия установлена поверх старой (тот же идентификатор расширения).** При `onInstalled` воркер ищет ключи
`chrome.storage.local` старой версии (`domainExceptions`, `proxies`, `proxyActive`) и базу IndexedDB `PacProxyManagerDB`.
Если находит, один раз преобразует данные (флаг `legacyMigrated`), записывая каждое хранилище одной пачкой, и увеличивает
ревизию. Профили без данных старой версии не затрагиваются (проба прерывается и удаляет пустую базу, которую сама же открыла).

**Б. Установлена рядом (другой идентификатор — обычный случай для распакованного расширения или нового листинга).**
Chrome не даёт одному расширению читать хранилище другого, поэтому данные нужно выгрузить из popup старой версии и вставить в
**Settings → Import from PAC Proxy Manager 1.x**:

1. Откройте popup старого расширения, щёлкните внутри правой кнопкой → *Просмотреть код* и откройте вкладку *Console*.
2. Вставьте (проверено на настоящей сборке 1.1.2):

```js
(async()=>{const kv=await chrome.storage.local.get(["domainExceptions","proxies","proxyActive","overridePacScript"]);const db=await new Promise((r,j)=>{const q=indexedDB.open("PacProxyManagerDB");q.onsuccess=()=>r(q.result);q.onerror=()=>j(q.error)});const pacScripts=await new Promise(r=>{const q=db.transaction("pacScripts").objectStore("pacScripts").getAll();q.onsuccess=()=>r(q.result)});const out=JSON.stringify({...kv,pacScripts});copy(out);return out.length+" chars copied"})()
```

3. Вставьте содержимое буфера обмена в поле импорта нового расширения и нажмите **Import**.

Одни только списки доменов можно вставить и в **Rules → Import**: парсер понимает старый формат «один домен в строке»,
а также `yes` / `no` как синонимы `PROXY` / `DIRECT`.

## Соответствие данных

| старая версия | новая |
|---|---|
| `domainExceptions[d] = 'yes'` | правило `d` → `PROXY` |
| `domainExceptions[d] = 'no'` | правило `d` → `DIRECT` |
| `domainExceptions[d] = 'pac'` | (старая версия для «PAC» ничего не хранила; отсутствие записи = режим по умолчанию) |
| `*.example.com` | `*.example.com` (та же семантика: сам домен и все поддомены) |
| `proxies[].url` (`socks5://h:p`, `http://…`) | `ProxyServer` (схема, хост, порт; порты по умолчанию 80/443/1080) |
| `pacScripts[]` с `sourceType: 'url'` | PAC-источник типа URL, последняя загруженная версия сохранена, обновление вручную |
| `pacScripts[]` с `sourceType: 'plain'` | PAC-источник, встроенный скрипт |
| `overridePacScript !== false` (при наличии прокси) | опция на вкладке PAC «использовать мои прокси вместо прокси из PAC» |
| `proxyActive` или любой включённый PAC-скрипт | главный переключатель ВКЛ |
| нет включённых PAC-скриптов | режим по умолчанию **Direct** (старая версия пускала через прокси только домены `yes`) |
| есть включённые PAC-скрипты | режим по умолчанию **PAC** |

Некорректные домены и прокси пропускаются и перечисляются в сообщении об импорте.

## Что переносится не один в один

- **«Override PAC proxies with mine»** (`overridePacScript` в старой версии) теперь называется **вкладка PAC →
  «Использовать мои прокси вместо прокси из PAC»**. Импортёр включает опцию, если настройка в старой версии была включена
  (по умолчанию так и было), у вас были прокси и прокси был активен.
- Старые PAC-скрипты вставлялись *внутрь* `function userPacScriptN(){…}`. Теперь каждый источник изолирован в своей области
  видимости функции. Это строже: скрипт, который рассчитывал на утечку глобальных переменных в другие скрипты, работать не будет.
- Старая версия ничего не обновляла автоматически. Импортированные URL-источники получают обновление «вручную»;
  интервал задаётся на вкладке PAC.
- Языковые пакеты старой версии (13 локалей) не переносятся: интерфейс новой версии на английском и русском.

Тесты: `tests/migration.test.ts` (преобразование, обработка мусора и сквозная проверка «старые данные → PAC → маршрутизация»).
